# Κατόψεις — «Editor που δουλεύει» (Design / Spec)

**Ημερομηνία:** 2026-10-29 · **Status:** εγκεκριμένο design, προς implementation plan.

## Σκοπός

Ένας **καθαρός, αξιόπιστος editor κάτοψης**: ο χρήστης ανοίγει μια κάτοψη και σε λίγα βήματα έχει **χρήσιμους, επεξεργάσιμους τοίχους** — με το AI να δίνει μια καλή **πρώτη εκδοχή** και τον χρήστη να τη **διορθώνει εύκολα**. Αντικαθιστά το σημερινό μπερδεμένο UI με πολλαπλές (μισοσπασμένες) διαδρομές ανίχνευσης.

**Αποδεκτός στόχος ανίχνευσης (συμφωνημένο):** AI best-effort πρώτη εκδοχή (ρεαλιστικά ~70–90%) + εύκολη χειροκίνητη διόρθωση. ΟΧΙ υπόσχεση τελειότητας.

**Ποιος/πού:** διαχειριστές στη `jordan`, μέσα στον v2 editor (`editorV2`, πλέον default-on), από παντού που ανοίγει ο `FloorPlanDialog` (πελάτης/δυνητικός/έργο).

## Εκτός scope (επόμενα sub-projects)

B: βιβλιοθήκη κατόψεων ανά πελάτη/δυνητικό (reuse από παντού). C: ροή προσφοράς (διάλεξε χώρο → τιμή). D: εξαγωγή reusable app-agnostic component. E: ξαναφτιάξιμο 3D. Αυτό το spec είναι **μόνο το A**.

## Ροή χρήστη (μία, καθαρή)

1. **Άνοιγμα κάτοψης** (εικόνα/PDF) στον v2 editor.
2. **Κλίμακα** — εργαλείο «Κλίμακα» (Κ) → γραμμή σε γνωστή απόσταση → μήκος σε μέτρα → «Εφαρμογή». *(ήδη υλοποιημένο)*
3. **Ανίχνευση τοίχων** — **ΕΝΑ** κουμπί «Ανίχνευση με AI» (όλο ή σε περιοχή) → **προεπισκόπηση** (κυανό) → **Αποδοχή** ή **Άκυρο**.
4. **Διόρθωση** — σχεδίαση/σβήσιμο/μετακίνηση τοίχων με snapping· πρόσθεσε ό,τι έλειψε, σβήσε ό,τι πιάστηκε λάθος.
5. **(προαιρετικά)** «Υπολογισμός χώρων» — από τα κλειστά περιγράμματα τοίχων βγαίνουν δωμάτια με εμβαδά.
6. **Αποθήκευση** στον owner.

**Δευτερεύον (όχι μπροστά):** «Εισαγωγή από CAD/PDF (vector layers)» μόνο για καθαρά διανυσματικά αρχεία με layers. **Πάντα διαθέσιμο:** χειροκίνητο draw.

## Συστατικά & αρχιτεκτονική

**Επαναχρησιμοποιούνται ως έχουν:** `editor/store.ts` (04b), `editor/interactions.ts` + `editor/snapping.ts` (04c/04d), `EditorShell`, `PlanViewer`, `lib/floorplan/ai.ts` + `lib/ai/vision-config.ts` (OpenRouter/Claude), `feature-flag` (default-on).

**Αφαιρούνται (σκουπίδια/σύγχυση):**
- Το UI «Διανυσματικοί τοίχοι» (raster vectorize): `previewVectorWalls`, `acceptVectorWalls`, `wallPreview` state, το σχετικό block στο `rightExtra`, και το `...(wallPreview ?? [])` από το `vectorWalls` prop.
- Το auto-populate effect που διανυσματοποιεί τη raster μάσκα στο άνοιγμα (παράγει το ίδιο 0,9% σκουπίδι).
- Το `combinedWallMask` + οι raster εξαρτήσεις μένουν ΜΟΝΟ αν τις χρειάζεται το CAD import· αλλιώς φεύγουν.

**Νέο / αλλάζει:**
1. **AI walls prompt (δυνατό)** — `FLOORPLAN_WALLS_PROMPT` (ήδη προσχέδιο): ΜΟΝΟ δομικοί τοίχοι ως centerlines· αυστηρά αγνοεί κείμενα/αριθμούς/διαστάσεις/διαγραμμίσεις/parking/κάδρο· προτιμά λίγους μακριούς ίσιους. Σχήμα `aiWallsResponse` + `parseAiWallsResponse` + `aiWallsToSegments` (ήδη προσχέδιο, με tests).
2. **AI → preview** — ο client στέλνει την εικόνα (ή crop) στο route (`mode=walls`, υπάρχει)· το αποτέλεσμα μπαίνει σε **preview state** (ΟΧΙ απευθείας στο store)· «Αποδοχή» → `store.addWalls`.
3. **Επιλογή περιοχής (crop)** — Shift+σύρσιμο ορίζει ορθογώνιο· σκανάρει μόνο εκείνο· τα αποτελέσματα μετατοπίζονται πίσω στις πλήρεις συντεταγμένες.
4. **Λαβές άκρων στην επεξεργασία** — επιλεγμένος τοίχος δείχνει λαβές στα a/b· σύρσιμο με snapping → `store.moveWallEnd`. (Αν δεν υπάρχει ήδη στον PlanViewer, προστίθεται.)
5. **walls → rooms** — καθαρή συνάρτηση `roomsFromWalls(walls, opts)` σε `lib/floorplan/editor/`: planar graph από τα τμήματα τοίχων (κόμβοι στα άκρα/τομές, εύρεση ελάχιστων κλειστών βρόχων/faces) → πολύγωνα δωματίων + εμβαδά. Καθαρή, με vitest.
6. **Καθαρό δεξί πάνελ** — σειρά: Κλίμακα → Ανίχνευση με AI (+preview Αποδοχή/Άκυρο) → Υπολογισμός χώρων → (δευτερεύον) CAD/PDF → Τύποι τοίχου. Το preview Αποδοχή/Άκυρο ΔΕΝ είναι gated σε `isPdf` (δουλεύει και για εικόνες).

**Συντεταγμένες:** editor σε px της `analysis`· `mPerPx` (κλίμακα) → μέτρα στο store. AI: 0–1000 → px (crop) → offset → μέτρα.

## Error handling

- Χωρίς κλίμακα (`mPerPx==null`): η Ανίχνευση/CAD/επιλογή-περιοχής είναι **ανενεργά** με σαφές tooltip «Όρισε πρώτα κλίμακα». (ήδη)
- AI route σφάλμα (χωρίς κλειδί/credits/αρνημένο): toast με το μήνυμα του παρόχου· κανένα crash. Fallback πάροχος (Google) ήδη στο vision-config.
- AI δεν βρήκε τοίχους: toast «δεν βρέθηκαν τοίχοι — δοκίμασε περιοχή ή σχεδίασε χειροκίνητα».
- Υπέρβαση ορίου (`walls.max 20.000`): `clampAcceptCount` κόβει με προειδοποίηση. (ήδη)
- `roomsFromWalls` με ανοιχτά περιγράμματα (ανοίγματα/κενά): βγάζει όσα κλειστά δωμάτια βρει· δεν σκάει σε μη-κλειστά.

## Testing

**Καθαρή λογική (vitest):** `parseAiWallsResponse`/`aiWallsToSegments` (ήδη)· `snapPoint`/`applyLength`/`wallsInRect`/`marqueeIds` (ήδη)· store `addWalls`/`moveWallEnd`/multi-select (ήδη)· **νέο** `roomsFromWalls` (κλειστό τετράγωνο → 1 δωμάτιο με σωστό εμβαδό· L-σχήμα· ανοιχτό περίγραμμα → 0· γειτονικά δωμάτια με κοινό τοίχο → 2).

**DOM + ποιότητα AI:** manual QA από τον χρήστη (έχει το OpenRouter key στο deploy· δεν υπάρχει pdfjs/E2E test infra). Το strong prompt + το preview κάνουν τα κακά αποτελέσματα **απορρίψιμα** πριν μπουν.
